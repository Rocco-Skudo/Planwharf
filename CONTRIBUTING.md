# Contributing to Planwharf

Thank you for your interest in Planwharf. Read [README.md](README.md), [AGENTS.md](AGENTS.md), and the documentation relevant to your change before opening a pull request.

Use English for documentation, product messages, comments, and commit messages. Keep changes focused. Preserve personal notebook data, existing workspace changes, and historical execution evidence. Use isolated notebooks and attempts for validation; inspection must not dispatch personal projects or push, merge, reset, or overwrite their files.

## Contributor License Agreements

External contributions are accepted only under the project's versioned Contributor License Agreements:

- If you own the contribution, accept [CLA.md](CLA.md) version 1.0.
- If an organization owns the contribution, it must accept [CLA-ENTITY.md](CLA-ENTITY.md) before the contribution is merged. Ordinary individual contributors do not need the Entity CLA.

For an individual contribution, include this exact statement in the pull request description or a pull request comment:

    I have read CLA.md (v1.0) and I accept it for this contribution
    and my subsequent contributions.

The statement accepts version 1.0 for that contribution and subsequent contributions until you notify the maintainer in writing that future submissions are excluded. Licenses already granted cannot be revoked. Opening a pull request alone does not accept the CLA. Entity acceptance follows the procedure in CLA-ENTITY.md; an employee's pull request alone does not accept it for an organization.

The contributor keeps copyright. The CLA grants rights for the official project to distribute the contribution under GPL-3.0-only and to offer parallel alternative or proprietary licenses. It commits to keeping the contribution available in the public GPL project. The contributor's royalty-free grant does not mean that a commercial license is offered free of charge.

Record acceptance in the pull request with the applicable CLA version. Do not publish private contributor details or completed Entity CLA schedules in the repository. These documents do not assert that previous contributors have accepted them; earlier contributions need their own verified rights before alternative licensing.

## Validation

Describe what changed and how it was verified. Run checks appropriate to the affected behavior; use [the README validation guidance](README.md#validation-and-historical-evidence). Do not fabricate model access, provider IDs, quotas, launches, or completion evidence. Keep original third-party notices with any included code or assets.
